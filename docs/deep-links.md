# Deep links — the full list of `kinkane.app` URLs the apps must handle

Every link below is generated by this backend and sent to a real person, in an
email, a push notification or a shared message. On a phone each one should open
the app rather than the mobile web page.

The set matters as a set: the association files match by path pattern, so a path
that isn't registered opens Safari or Chrome instead, and the user lands on a web
page asking them to log in again. There is no error and nothing to debug — it
just quietly stops feeling like an app.

All paths are relative to `APP_URL` (`https://kinkane.app` in production — the
`.app` domain, not `.com`; see [config/index.ts](../src/config/index.ts)).

## Must be deep links

| Path | Where it comes from | Notes |
| --- | --- | --- |
| `/r/:code` | shared referral links | slug-less form — chat clients clip the last path segment |
| `/r/:code/:slug` | `buildReferralLink()`, referral invite emails, share sheets | `?c=` share channel rides along and must be forwarded |
| `/invite?ref=CODE&c=CHANNEL&cid=CLICKID` | where `/r/*` redirects on the web | reached when the app *wasn't* installed at tap time |
| `/books/:bookId` | new-recommendation email | |
| `/explore` | subscription-confirmed email | |
| `/subscribe` | trial-ending email | |
| `/account/subscription` | payment-failed and cancellation emails, `upgradeUrl` on 402 responses | |
| `/account/subscription?checkout=success` | Stripe subscription checkout return | |
| `/account/subscription?checkout=cancelled` | Stripe subscription checkout return | |
| `/orders?checkout=success&orderId=N` | Stripe order checkout return | |
| `/cart?checkout=cancelled&orderId=N` | Stripe order checkout return | |
| `/reset-password?token=TOKEN` | password-reset email | |
| `/cancel-email-change?token=TOKEN` | email-change notice to the old address | |
| `/` | welcome, follow-request and weekly-digest emails | bare host — send it to the app's home tab |

## Deliberately *not* deep links

Register these as exclusions, not omissions — a wildcard that swallows them
would be worse than no deep linking at all.

| Path | Why |
| --- | --- |
| `/unsubscribe?token=TOKEN` | must work for someone who has deleted the app, and often opens in a webmail browser with no app session |
| `/privacy` | email footer, linked for readers who are not users |
| `/terms` | email footer, linked for readers who are not users |
| `/about` | `REFERRAL_VIDEO_URL` default — a public marketing page |

## Two things that are easy to get wrong

**The Stripe returns carry state in the query string.** `?checkout=success` and
`?orderId=` are the only signal the app gets that a payment completed — the
webhook is what actually updates the account, but the redirect is what tells the
UI to stop showing a spinner. A handler that matches the path and drops the query
string will strand the user on a screen that never resolves.

**Tokens are single-use and short-lived.** `/reset-password` and
`/cancel-email-change` links are frequently opened on a different device from the
one the app is installed on. They must keep working in a plain browser; deep
linking them is an improvement for the common case, not a replacement for the web
page.
